6. TASK, ASSISTANCE MODE VÀ SECTION ĐỘNG
-----------------------------------------
Tạo task (mở rộng API cũ):
POST /api/tasks
Authorization: Bearer <JWT>
Body:
{
  "documentId": <document_id>,
  "sessionId": <session_id>,
  "taskType": "MANUAL",
  "assignedTo": <user_id>,
  "dueAt": "2030-01-31T17:00:00",
  "assistanceMode": "NONE"
}

assistanceMode chỉ nhận NONE hoặc AI_ASSISTED. Task AI luôn dùng AI_ASSISTED.
Backend từ chối chạy AI cho manual task có assistanceMode = NONE.

Đánh dấu bắt đầu một section động:
PATCH /api/tasks/<task_id>/sections/<field_key>
Body: { "status": "IN_PROGRESS" }

Section được sinh từ annotations.label_name; field_key là tên đã chuẩn hóa để ghép
kết quả A/B, còn field_name giữ tên gốc để hiển thị. Khi lưu labels, section tự
chuyển SAVED; khi submit task, section tự chuyển SUBMITTED.


7. WORK TIME TRACKING
----------------------
Tất cả API cần Authorization: Bearer <JWT>.

Bắt đầu lượt làm việc (chỉ được truyền đúng một ID):
POST /api/work-time/start
Body task:        { "taskId": <task_id> }
Body review case: { "reviewCaseId": <review_case_id> }

Response data mẫu:
{
  "id": <work_time_entry_id>,
  "task_id": <task_id>,
  "review_case_id": null,
  "active_seconds": 0,
  "started_at": "2030-01-20T08:00:00",
  "last_heartbeat_at": "2030-01-20T08:00:00"
}

Heartbeat:
POST /api/work-time/<work_time_entry_id>/heartbeat
Body: không có. Mỗi lần chỉ cộng tối đa 45 giây và lượt mở được tái sử dụng để
không nhân đôi thời gian khi mở nhiều tab.

Dừng lượt:
POST /api/work-time/<work_time_entry_id>/stop
Body: { "reason": "SAVE" }
reason: SAVE, SUBMIT, COMPLETE, PAGE_HIDDEN, IDLE, MANUAL hoặc STALE.

Lỗi thường gặp:
- HTTP 400: truyền cả taskId và reviewCaseId, không truyền ID nào, hoặc reason sai.
- HTTP 403: task/case không được phân công cho tài khoản hiện tại.
- HTTP 404: task, review case hoặc work-time entry không tồn tại.
- HTTP 409: đối tượng đã hoàn thành hoặc trạng thái không cho phép ghi thời gian.


8. REVIEW CASE
---------------
Manager tạo case từ hai task đã submit của cùng một PDF:
POST /api/review-cases
Body:
{
  "leftTaskId": <left_task_id>,
  "rightTaskId": <right_task_id>,
  "assignedTo": <reviewer_user_id>,
  "dueAt": "2030-02-01T17:00:00"
}

Danh sách case:
GET /api/review-cases
GET /api/review-cases?status=PENDING

Chi tiết case, nguồn A/B, section động, bbox và quyết định:
GET /api/review-cases/<review_case_id>

Các comparisonType trả về: EXACT, FORMAT_ONLY, VALUE_DIFFERENT, MISSING.
FORMAT_ONLY chỉ cho biết hai giá trị tương đương về số nhưng khác cách viết;
Reviewer vẫn phải chọn hoặc nhập giá trị cuối cùng.

Lưu quyết định một field:
PUT /api/review-cases/<review_case_id>/fields/<field_key>
Body chọn A:
{
  "selectedSource": "LEFT",
  "finalValue": "1.000",
  "feedback": "Giữ định dạng theo báo cáo"
}

selectedSource nhận LEFT, RIGHT hoặc CUSTOM. finalValue luôn bắt buộc.

Hoàn thành case:
POST /api/review-cases/<review_case_id>/complete
Body: không có.

Lỗi thường gặp:
- HTTP 400: cùng task, khác document/PDF, deadline quá khứ hoặc payload sai.
- HTTP 403: không phải Manager khi tạo case, hoặc không phải Reviewer được giao.
- HTTP 404: task/case/field không tồn tại.
- HTTP 409: source task chưa submit, field khác biệt chưa chốt, hoặc case đã đóng.


9. MANAGER STATISTICS
----------------------
GET /api/statistics
GET /api/statistics?sessionId=<session_id>&from=2030-01-01T00:00:00&to=2030-01-31T23:59:59

Response giữ nguyên các trường cũ và bổ sung:
- sectionProgress: tiến độ task/section động.
- userProductivity: khối lượng và section theo người.
- timeComparison: trung bình, trung vị và cỡ mẫu theo NONE/AI_ASSISTED.
- overdueTasks: task quá hạn.
- reviewCases: số case theo trạng thái/deadline.


10. VÍ DỤ POWERSHELL CHO WORKFLOW MỚI
--------------------------------------
$headers = @{ Authorization = "Bearer <JWT>" }
$base = "http://localhost:8080/api"

$timer = Invoke-RestMethod -Method Post -Uri "$base/work-time/start" `
  -Headers $headers -ContentType "application/json" `
  -Body (@{ taskId = <task_id> } | ConvertTo-Json)

$entryId = $timer.data.id
Invoke-RestMethod -Method Post -Uri "$base/work-time/$entryId/heartbeat" `
  -Headers $headers
Invoke-RestMethod -Method Post -Uri "$base/work-time/$entryId/stop" `
  -Headers $headers -ContentType "application/json" `
  -Body (@{ reason = "SAVE" } | ConvertTo-Json)

$caseBody = @{
  leftTaskId = <left_task_id>
  rightTaskId = <right_task_id>
  assignedTo = <reviewer_user_id>
  dueAt = "2030-02-01T17:00:00"
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri "$base/review-cases" `
  -Headers $headers -ContentType "application/json" -Body $caseBody

Invoke-RestMethod -Method Get `
  -Uri "$base/statistics?sessionId=<session_id>" -Headers $headers

LƯU Ý KẾT NỐI DATABASE
-----------------------
pgAdmin 4 là công cụ quản trị. Backend kết nối trực tiếp tới PostgreSQL server chứa
database aair_db, không kết nối vào ứng dụng pgAdmin 4.

Biến môi trường backend:
- DB_URL      : jdbc:postgresql://localhost:5432/aair_db
- DB_USERNAME : tên user PostgreSQL, ví dụ postgres
- DB_PASSWORD : mật khẩu của user PostgreSQL
- JWT_SECRET  : chuỗi bí mật tối thiểu 32 ký tự (bắt buộc đổi khi triển khai thật)
- FRONTEND_ORIGIN: http://localhost:5173


1. API ĐĂNG NHẬP
----------------
Method: POST
URL: /api/auth/login
Content-Type: application/json
Authorization: Không cần

Tham số đầu vào (JSON body):
+----------+--------+----------+----------------------------------------------+
| Tên      | Kiểu   | Bắt buộc | Mô tả                                        |
+----------+--------+----------+----------------------------------------------+
| username | string | Có       | Tên tài khoản, tối đa 50 ký tự              |
| password | string | Có       | Mật khẩu gốc do người dùng nhập             |
+----------+--------+----------+----------------------------------------------+

Ví dụ request:
{
  "username": "<username>",
  "password": "<password>"
}

Tham số trả về khi thành công - HTTP 200:
+------------------------+---------+----------------------------------------------+
| Trường                 | Kiểu    | Mô tả                                        |
+------------------------+---------+----------------------------------------------+
| success                | boolean | true                                         |
| message                | string  | Thông báo kết quả                            |
| data.accessToken       | string  | JWT dùng cho API cần đăng nhập               |
| data.tokenType         | string  | Luôn là Bearer                               |
| data.expiresIn         | number  | Thời gian hiệu lực token, đơn vị giây        |
| data.user.id           | number  | ID tài khoản                                 |
| data.user.username     | string  | Tên tài khoản                                |
| data.user.role         | string  | Vai trò                                      |
| data.user.isActive     | boolean | Trạng thái hoạt động                         |
| data.user.createdAt    | string  | Ngày giờ tạo theo ISO-8601                   |
| data.user.redirectPath | string  | Trang HTML cần chuyển tới sau đăng nhập      |
+------------------------+---------+----------------------------------------------+

Ví dụ response thành công:
{
  "success": true,
  "message": "Đăng nhập thành công",
  "data": {
    "accessToken": "eyJhbGciOiJIUzI1NiJ9...",
    "tokenType": "Bearer",
    "expiresIn": 28800,
    "user": {
      "id": 1,
      "username": "<username>",
      "role": "TERMINOLOGY",
      "isActive": true,
      "createdAt": "2026-08-29T14:30:00",
      "redirectPath": "/main/HTML/User/Terminology/Dashboard.html"
    }
  }
}

Các lỗi có thể trả về:
- HTTP 400 / VALIDATION_ERROR: thiếu username/password hoặc dữ liệu sai định dạng.
- HTTP 401 / INVALID_CREDENTIALS: sai tên tài khoản hoặc mật khẩu.
- HTTP 403 / ACCOUNT_INACTIVE: tài khoản đã bị khóa (is_active = false).

Ví dụ response sai tài khoản hoặc mật khẩu - HTTP 401:
{
  "success": false,
  "code": "INVALID_CREDENTIALS",
  "message": "Tên tài khoản hoặc mật khẩu không chính xác",
  "timestamp": "2026-08-29T14:31:00",
  "details": {}
}

11. USER AVATAR
---------------
Trước khi khởi động backend có hỗ trợ avatar, chạy thủ công file sau trong
pgAdmin 4 (Query Tool) trên đúng database của hệ thống:

database/add_user_avatar.sql

Migration này idempotent và chỉ thêm users.avatar_url. Không lưu nội dung ảnh
trong PostgreSQL. Ảnh được lưu tại <app.storage.directory>/avatars; cấu hình mặc
định tương ứng với thư mục uploads/avatars của backend.

API tạo/cập nhật user dạng JSON được giữ nguyên. Sau khi đã có user ID, upload
avatar bằng endpoint riêng:

Method: POST
URL: /api/users/<user_id>/avatar
Authorization: Bearer <JWT>
Content-Type: multipart/form-data
Form field: file

Quy tắc kiểm tra:
- Chỉ nhận JPG/JPEG, PNG hoặc WEBP.
- Dung lượng tối đa 2 MB.
- Backend kiểm tra phần mở rộng, MIME type và chữ ký thực của tệp.
- Chỉ ADMIN hoặc MANAGER có quyền WRITE User Management mới được cập nhật.

Response thành công - HTTP 200:
{
  "success": true,
  "message": "Thành công",
  "data": {
    "id": <user_id>,
    "username": "<username>",
    "avatar_url": "/uploads/avatars/<generated-file-name>.png"
  }
}

Ảnh được đọc trực tiếp tại:
GET /uploads/avatars/<generated-file-name>.png

Ví dụ PowerShell:
$avatar = Get-Item "<path-to-avatar.png>"
Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:8080/api/users/<user_id>/avatar" `
  -Headers @{ Authorization = "Bearer $token" } `
  -Form @{ file = $avatar }

Lỗi thường gặp:
- HTTP 400: file rỗng, lớn hơn 2 MB, sai phần mở rộng/MIME/chữ ký ảnh.
- HTTP 403: không có quyền cập nhật User Management.
- HTTP 404: user ID không tồn tại.
